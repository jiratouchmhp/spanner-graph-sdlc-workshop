# REQ-006: Zero-Trust mTLS & Scoped OIDC Authorization

- **Framework:** `ZERO_TRUST`
- **Severity:** `CRITICAL`
- **Owner:** `team-security` (`#security-iam`)
- **Applicable APIs:** `api-auth-token-v2` (`COMPLIANT`), `api-auth-jwks-v2` (`COMPLIANT`), `api-payments-charge-v2` (`COMPLIANT`), `api-ledger-post-v2` (`COMPLIANT`), `api-fraud-score-v1` (`COMPLIANT`), `api-partner-checkout-v1` (`COMPLIANT`)
- **Applicable Services:** `svc-auth` (`COMPLIANT`), `svc-payments` (`COMPLIANT`), `svc-ledger` (`COMPLIANT`)
- **Related ADRs:** `ADR-006`

## Zero-Trust Mandate

Network location alone MUST NEVER grant trust inside Acme Commerce clusters. Every service-to-service API invocation MUST establish mutually authenticated encrypted transport (**mTLS**) and present a cryptographically verifiable, least-privilege **OIDC** bearer token.

## Implementation Controls

1. **TLS 1.3 mTLS:** All 10 mesh-integrated services authenticate using SPIFFE workload certificates rotated automatically every 24 hours (`ADR-006`).
2. **Short-Lived Scoped OIDC Tokens:** Workloads call `svc-auth` via `api-auth-token-v2` (`POST /v2/auth/token`) to obtain 5-minute JWTs bound to the caller's workload identity, target service audience, and narrow permission scope.
3. **Stateless Signature Validation:** Receiving services verify JWT signatures locally against `api-auth-jwks-v2` and reject expired, wrong-audience, or missing-scope tokens with HTTP `401`/`403`.
4. **Agent Identity Binding:** AI agents accessing operational knowledge graphs via MCP Toolbox MUST bind caller email server-side via OIDC and NEVER accept caller identity as a model-supplied argument.
