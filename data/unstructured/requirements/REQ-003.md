# REQ-003: High-Value (`> $500`) Fail-Closed Fraud Scoring Gate

- **Framework:** `RISK_POLICY`
- **Severity:** `CRITICAL`
- **Owner:** `team-risk` (`#risk-fraud`)
- **Applicable APIs:** `api-payments-charge-v2` (`COMPLIANT`), `api-fraud-score-v1` (`COMPLIANT`), `api-fraud-rules-v2` (`COMPLIANT`), `api-checkout-submit-v1` (`COMPLIANT`)
- **Applicable Services:** `svc-fraud` (`COMPLIANT`), `svc-payments` (`COMPLIANT`)
- **Related ADRs:** `ADR-004`

## Risk Policy Mandate

To prevent high-ticket chargeback spikes during fraud-engine latency anomalies or partial outages, Acme Commerce enforces an asymmetric failure posture keyed on transaction value (`$500` USD equivalent threshold).

## Enforcement Rules

1. **Mandatory Fail-Closed Above `$500`:** Any charge request on `api-payments-charge-v2` or `api-checkout-submit-v1` with transaction value `> $500` MUST receive an explicit `APPROVE` response from `svc-fraud` (`api-fraud-score-v1`) within the `45ms` timeout (`ADR-004`, `REQ-002`). If `api-fraud-score-v1` times out, returns HTTP `5xx`, or is unreachable, `svc-payments` MUST **fail-closed** and reject the charge with HTTP `503` (`FRAUD_GATE_TIMEOUT`).
2. **Controlled Fallback at or Below `$500`:** Transactions `<= $500` may degrade to deterministic velocity checks on `api-fraud-rules-v2` (`35ms` budget) with mandatory post-authorization async review queued for `team-risk`.
3. **Zero Silent Bypass:** Feature flags disabling the fail-closed gate on `> $500` traffic require dual sign-off from `team-risk` and `team-security`.
