# REQ-011: Distributed Trace Propagation & Structured DB Request Tags

- **Framework:** `OBSERVABILITY`
- **Severity:** `MEDIUM`
- **Owner:** `team-integrations` (`#partner-messaging`)
- **Applicable Services:** `svc-notifications` (`COMPLIANT`)
- **Related ADRs:** `ADR-007`

## End-to-End Observability Standard

To diagnose multi-hop latency spikes across `svc-partner-gw`, `svc-orders`, `svc-checkout`, `svc-payments`, `svc-fraud`, `svc-ledger`, and asynchronous workers (`svc-notifications`, `svc-webhooks`), every request MUST carry correlated distributed trace context and structured database tags.

## Required Controls

1. **W3C `traceparent` Propagation:** All synchronous REST calls and CloudEvents async envelopes (`ADR-007`) MUST propagate `traceparent` and `tracestate` headers end to end.
2. **Cloud Spanner Request & Transaction Tags:** Every database read and write MUST attach `request_tag` and `transaction_tag` labels (for example `svc-payments:charge-v2`) so `SPANNER_SYS.QUERY_STATS_TOP_HOUR` and `SPANNER_SYS.LOCK_STATS_TOP_HOUR` attribute CPU and lock waits directly to the originating API and team.
3. **MCP Telemetry:** Agentic queries routed through MCP Toolbox enable SQL commenter tags and GCP OpenTelemetry tracing.
