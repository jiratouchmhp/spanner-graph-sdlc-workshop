# REQ-002: Tier-0 Payment Latency (`p99 <= 180ms`, Fraud `<= 45ms`, `99.99%` SLA)

- **Framework:** `SLA`
- **Severity:** `CRITICAL`
- **Owner:** `team-payments` (`#payments-eng`)
- **Applicable APIs:** `api-payments-charge-v2` (`COMPLIANT`), `api-payments-refund-v2` (`COMPLIANT`), `api-fraud-score-v1` (`COMPLIANT`), `api-fraud-rules-v2` (`COMPLIANT`)
- **Applicable Services:** `svc-payments` (`COMPLIANT`), `svc-fraud` (`COMPLIANT`)
- **Related ADRs:** `ADR-004`, `ADR-008`

## Availability & Latency Objective

Revenue-critical Tier-0 payment processing MUST maintain **99.99%** monthly availability (<= 4.38 minutes of unplanned downtime per month) across three synchronous zones (`asia-southeast3-a/b/c`) in Bangkok Cloud Spanner and meet strict tail-latency budgets during peak seasonal traffic.

## Component Latency Breakdown

| Stage | Target Service / API | p99 Budget | Enforcement Mechanism |
| :--- | :--- | ---: | :--- |
| Token Verification | `svc-auth` (`api-auth-jwks-v2` cached) | `<= 2ms` | Local JWKS signature cache (`ADR-006`) |
| Fraud Risk Gate | `svc-fraud` (`api-fraud-score-v1`, `api-fraud-rules-v2`) | `<= 45ms` | Hard RPC deadline; fail-closed for `> $500` (`REQ-003`) |
| Acquirer Auth + Ledger | `svc-ledger` (`api-ledger-post-v2` `<= 60ms`) | `<= 120ms` | Co-located Bangkok regional Spanner (`ADR-008`) |
| **End-to-End Charge** | **`svc-payments` (`api-payments-charge-v2`)** | **`<= 180ms`** | SLO burn-rate alerts page `team-payments` & `team-risk` |

Any proposed modification to `api-payments-charge-v2` MUST prove p99 latency remains `<= 180ms` and synchronous fraud calls remain `<= 45ms` under 2x peak load tests.
