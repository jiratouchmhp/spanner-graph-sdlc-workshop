# REQ-008: 180-Day Breaking Change Freeze for Tier-0 APIs

- **Framework:** `CHANGE_MGMT`
- **Severity:** `HIGH`
- **Owner:** `team-payments` (`#payments-eng`)
- **Applicable APIs:** `api-payments-refund-v2` (`COMPLIANT`), `api-checkout-submit-v1` (`COMPLIANT`)
- **Applicable Services:** `svc-payments` (`COMPLIANT`), `svc-checkout` (`COMPLIANT`)
- **Related ADRs:** `ADR-010`, `ADR-003`

## Change Management Standard

Operationalizing `ADR-010`, every `Tier-0` API exposed by `svc-payments` and `svc-checkout` (including `api-payments-charge-v2`, `api-payments-refund-v2`, and `api-checkout-submit-v1`) is protected by a mandatory **180-day** breaking-change freeze window.

## Pre-Release Verification Gate

1. **Automated Graph Blast-Radius Audit:** Before scheduling any breaking contract change, owners MUST query the SDLC Knowledge Graph to enumerate all direct synchronous callers, transitive upstream consumers, and `DATA_FEED` subscribers.
2. **Parallel Version Support:** The retiring contract MUST remain fully supported alongside the successor version for the full `180-day` window while telemetry monitors caller migration.
3. **Escalation Lead Sign-Off:** Written approval is required from every impacted Tier-0 and Tier-1 owning team (`team-payments`, `team-checkout`, `team-billing`, `team-integrations`) prior to sunset execution.
