# ADR-006: Zero-Trust Service-to-Service mTLS & Short-Lived OIDC Tokens

- **Status:** `ACCEPTED`
- **Owner:** `team-security` (`#security-iam`)
- **Decision Date:** `2024-11-18`
- **Governed APIs:** `api-auth-token-v2` (`MANDATES`), `api-auth-jwks-v2` (`MANDATES`), `api-partner-checkout-v1` (`MANDATES`), `api-payments-charge-v2` (`CONSTRAINS`), `api-payments-charge-v1` (`CONSTRAINS`), `api-checkout-submit-v1` (`CONSTRAINS`), `api-billing-invoice-v1` (`CONSTRAINS`), `api-fraud-score-v1` (`CONSTRAINS`), `api-ledger-post-v2` (`CONSTRAINS`)

## Context

Static API keys and perimeter-only VPC firewall rules allowed lateral movement if a single Tier-2 workload was compromised. Satisfying `REQ-006` and `REQ-001` requires cryptographic workload identity and least-privilege audience scoping on every east-west RPC.

## Decision

1. **Mandatory Mutual TLS (mTLS):** All east-west service traffic across `svc-payments`, `svc-checkout`, `svc-billing`, `svc-orders`, `svc-partner-gw`, `svc-notifications`, `svc-webhooks`, `svc-fraud`, `svc-ledger`, and `svc-inventory` MUST negotiate TLS 1.3 mTLS using short-lived SPIFFE workload certificates rotated every 24 hours.
2. **5-Minute Scoped OIDC Tokens via `svc-auth`:** Callers exchange their mTLS workload identity at `api-auth-token-v2` (`POST /v2/auth/token`) for a 5-minute OIDC JWT scoped to a specific target audience and action (for example `payments:charge:write`).
3. **Stateless JWKS Verification:** Receiving APIs validate JWT signatures locally using keys cached from `api-auth-jwks-v2` (`GET /v2/auth/.well-known/jwks.json`), keeping token verification overhead below `2ms`.

## Consequences

- **High-Fanin Criticality Hub:** Because 10 services depend directly on `svc-auth` and call `api-auth-token-v2`, `svc-auth` is classified `TIER_0` / `CRITICAL` with a `99.99%` SLA and ranks highest in graph `PageRank` criticality analyses.
- **No Static Secrets:** Long-lived static bearer keys are prohibited across all production services and MCP agent connectors.
