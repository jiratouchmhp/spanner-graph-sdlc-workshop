# Cloud Spanner Dialects, Transactions, Key-Value APIs, Change Streams & Queues

Self-contained reference for choosing between **GoogleSQL** and **PostgreSQL**, resolving dialect syntax and behavioral differences, handling Cloud Spanner's lack of general analytic window functions, applying SQL hints, configuring DML/PDML/Batch Write/Transactions/Reads, building Key-Value workloads, and operating Change Streams and Spanner Queues.

## 1. GoogleSQL vs PostgreSQL Dialect Selection

The SQL dialect is configured **per database at creation time** (`--database-dialect=GOOGLE_STANDARD_SQL` [default] or `POSTGRESQL`) and is **immutable**. A single Spanner instance can host both GoogleSQL and PostgreSQL databases simultaneously on the same Paxos/TrueTime storage engine.

- **Choose GoogleSQL when**: Building greenfield GCP services, using **Spanner Graph (GQL — GoogleSQL ONLY)**, calling Vertex AI via **`CREATE MODEL` DDL**, using Protobuf columns/bundles, aligning with BigQuery SQL syntax, or operating with native `gcloud spanner cli`.
- **Choose PostgreSQL when**: Migrating existing PostgreSQL applications, keeping open-source PostgreSQL drivers (`psycopg2/3`, `pgx`, `node-postgres`, `Npgsql`, PG JDBC) and ORMs (Hibernate, Spring Data JPA, GORM, SQLAlchemy 2, Prisma, Drizzle, Liquibase) via **PGAdapter**, or using `psql` tooling.

### Unsupported PostgreSQL Features on Spanner

- Triggers, `SAVEPOINT`, Transactional DDL, Partial indexes (except `WHERE col IS NOT NULL`), PostgreSQL Extensions, Server-side Foreign Data Wrappers (use `postgres_fdw` client-side via PGAdapter), User-Defined Types/Functions/Operators/Stored Procedures, `pgAdmin` control-plane actions, `DROP SCHEMA ... CASCADE`.
- **Nuance on `SERIAL` / `BIGSERIAL` / `SMALLSERIAL` (`serial2`/`serial4`/`serial8`)**: Monotonic OSS PostgreSQL counters are **not** supported (they cause split hotspots). However, Spanner PostgreSQL **does** support `SERIAL`/`BIGSERIAL`/`SMALLSERIAL` as DDL aliases for **bit-reversed positive `bigint` `IDENTITY` columns** after setting `ALTER DATABASE {database_id} SET spanner.default_sequence_kind = 'bit_reversed_positive';` (serialized by `GetDatabaseDDL` as `GENERATED BY DEFAULT AS IDENTITY`).

### 6 Critical PostgreSQL Behavioral Divergences from OSS PostgreSQL

1. **`float8` underflow**: Truncates silently to `0` instead of raising an underflow error.
2. **`concat()` with `NULL`**: Returns `NULL` if *any* argument is `NULL` (OSS PostgreSQL ignores `NULL` arguments).
3. **`array_cat()` and `||` with `NULL`**: Returns `NULL` if *any* argument is `NULL`.
4. **`array_to_string()` with `NULL` `null_string`**: Returns `NULL` if the optional `null_string` argument is `NULL`.
5. **Global case-insensitive object namespace**: All identifiers across ALL object types share one case-insensitive namespace (e.g., you cannot have table `MyTable` and schema `MYTABLE`). Unquoted identifiers fold to lowercase and are not case-preserving.
6. **HLL++ `numeric` incompatibility**: HyperLogLog++ sketches over GoogleSQL `NUMERIC` and PostgreSQL `numeric` are **not mergeable**.

## 2. GoogleSQL vs PostgreSQL Syntax Rosetta Stone

| Feature | GoogleSQL Syntax | PostgreSQL Syntax |
| :--- | :--- | :--- |
| **Query Parameters** | `@param_name` | `$1, $2, ...` |
| **SQL Hints** | `@{KEY=VAL}` (prefix statement, after table/join/group) | `/*@ KEY=VAL */` |
| **Primary Key in `CREATE TABLE`** | `CREATE TABLE T (Id INT64) PRIMARY KEY (Id)` (trailing) | `CREATE TABLE t (id bigint PRIMARY KEY)` (inline) |
| **Covering Secondary Index** | `CREATE INDEX Idx ON T(Col) STORING (Val)` | `CREATE INDEX idx ON t(col) INCLUDE (val)` |
| **TTL Row Deletion Policy** | `ROW DELETION POLICY (OLDER_THAN(Ts, INTERVAL 30 DAY))` | `TTL INTERVAL '30 days' ON ts` |
| **Database Options** | `ALTER DATABASE db SET OPTIONS (opt = val)` (clear: `NULL`) | `ALTER DATABASE db SET spanner.opt = val` (clear: `DEFAULT` or `RESET spanner.opt`) |
| **Default Time Zone Gotcha** | `default_time_zone` (defaults `America/Los_Angeles`; **empty DB with zero tables ONLY**) | `spanner.default_time_zone` (same empty-DB constraint!) |
| **Returning DML** | `INSERT/UPDATE/DELETE ... THEN RETURN [WITH ACTION] ...` | `INSERT/UPDATE/DELETE ... RETURNING ...` |
| **Sequences (Only Kind)** | `CREATE SEQUENCE s OPTIONS (sequence_kind='bit_reversed_positive', skip_range_min=1, skip_range_max=1000, start_with_counter=5000)` | `CREATE SEQUENCE s BIT_REVERSED_POSITIVE SKIP RANGE 1 1000 START COUNTER WITH 5000` |
| **Vector Column Type** | `ARRAY<FLOAT32>(vector_length=>768)` | `float4[] VECTOR LENGTH 768` |
| **Vector Index & Rebuild** | `CREATE VECTOR INDEX ... OPTIONS(...)` / `ALTER VECTOR INDEX ... REBUILD` | `CREATE INDEX ... USING scann (...) WITH (...)` / `REINDEX INDEX CONCURRENTLY ...` |
| **Locality Group** | `CREATE LOCALITY GROUP g OPTIONS (storage='ssd', ssd_to_hdd_spill_timespan='7d')` | `CREATE LOCALITY GROUP g STORAGE 'ssd' SSD_TO_HDD_SPILL_TIMESPAN '7d'` |
| **Placement** | `CREATE PLACEMENT p OPTIONS (instance_partition='ip1', default_leader='...')` | `CREATE PLACEMENT p WITH (instance_partition='ip1', default_leader='...')` |
| **Statistics GC Pin** | `ALTER STATISTICS pkg SET OPTIONS (allow_gc=false)` | `ALTER STATISTICS spanner."pkg" SET OPTIONS (allow_gc = false)` |
| **`INFORMATION_SCHEMA` Default Schema** | `WHERE SCHEMA_NAME = ""` | `WHERE schema_name = 'public'` |
| **`TABLESAMPLE`** | `BERNOULLI`, `RESERVOIR`; supports subquery-derived tables | `BERNOULLI`, `SPANNER.RESERVOIR`; **no** subquery-derived table sampling |
| **Remote AI Model DDL** | `CREATE MODEL m INPUT(...) OUTPUT(...) REMOTE OPTIONS(endpoint='...', default_batch_size=1..10)` (auto-creates Spanner service agent) | Not supported via PG DDL (use GoogleSQL DB or external Vertex AI client) |
| **Analytic / Window Functions** | **NOT supported** in general SQL (use `UNNEST(ARRAY(...)) WITH OFFSET` or BigQuery `EXTERNAL_QUERY`) | **NOT supported** in Spanner (offload to BigQuery `EXTERNAL_QUERY`) |

## 3. Non-Negotiable Limit: No General `ROW_NUMBER()` or Analytic Window Functions

Cloud Spanner (both GoogleSQL and PostgreSQL) has **NO** general `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, `LAG()`, `LEAD()`, or general SQL `OVER (...)` window functions. Although `WINDOW` is a reserved lexical keyword, Spanner rejects general SQL analytic window functions in `SELECT`, DML, and generated columns.

### Pattern A: Top-K Ranking & Reciprocal Rank Fusion (RRF) via `UNNEST(ARRAY(...)) WITH OFFSET`

```sql
-- GoogleSQL replacement for ROW_NUMBER() OVER (ORDER BY score DESC)
SELECT
  rank + 1 AS rank_1based,   -- WITH OFFSET is 0-based (0, 1, 2, ...)
  item.item_id,
  item.score
FROM UNNEST(ARRAY(
  SELECT AS STRUCT item_id, score
  FROM {table_name}
  ORDER BY score DESC
  LIMIT 100                  -- Always bound LIMIT to cap in-memory ARRAY materialization
)) AS item WITH OFFSET AS rank;
```

- `UNNEST` destroys array element order unless `WITH OFFSET [AS alias]` is attached.
- **Narrow GQL-Only Exception**: Spanner Graph GQL supports a single boolean windowed predicate, `IS_FIRST(k) OVER ([PARTITION BY ...] [ORDER BY ...])`, strictly inside GQL `FILTER` clauses (e.g., super-node edge capping; `k` must be positive; omits deterministic tie-breaking if `ORDER BY` is omitted). It cannot produce numeric ranks in general SQL `SELECT` clauses.

### Pattern B: General Analytic Window Functions via BigQuery Federated `EXTERNAL_QUERY`

For workloads requiring true `RANK()`, `DENSE_RANK()`, `LAG()`, `LEAD()`, or running window sums over live Spanner data, execute the window function in BigQuery via `EXTERNAL_QUERY` (enable **Spanner Data Boost** + parallel reads on the BigQuery connection, requiring `roles/bigquery.connectionUser` + Spanner reader roles; or use a BigQuery Spanner external dataset, which requires `roles/spanner.databaseReaderWithDataBoost`):

```sql
-- Execute in BigQuery against a Cloud Spanner connection (e.g., asia-southeast3)
SELECT
  c.customer_id,
  c.region_code,
  RANK() OVER (PARTITION BY c.region_code ORDER BY rq.total_orders DESC) AS region_rank
FROM `{project_id}.{bq_dataset}.customers` AS c
LEFT OUTER JOIN EXTERNAL_QUERY(
  '{project_id}.{bq_location}.{connection_id}',
  '''SELECT @{scan_method=columnar} customer_id, COUNT(*) AS total_orders
     FROM {table_name}
     GROUP BY customer_id'''
) AS rq
  ON rq.customer_id = c.customer_id
ORDER BY region_rank ASC;
```

## 4. Essential Optimizer & Execution Hints

- **Statement Hints** (`@{...}` GoogleSQL / `/*@ ... */` PG):
  - `USE_ADDITIONAL_PARALLELISM=TRUE|FALSE`
  - `LOCK_SCANNED_RANGES=exclusive|shared` (**cannot** combine with `SELECT ... FOR UPDATE`!)
  - `SCAN_METHOD=BATCH|ROW|COLUMNAR|NO_COLUMNAR` and `EXECUTION_METHOD=BATCH|ROW` (**never** pass `AUTO` or `DEFAULT` explicitly — omit the hint for default behavior!)
  - `ALLOW_TIMESTAMP_PREDICATE_PUSHDOWN=TRUE|FALSE`
  - `OPTIMIZER_VERSION=9|latest_version|default_version`, `OPTIMIZER_STATISTICS_PACKAGE=<pkg>|latest`
  - `AUTO_PARAMETER="ON"|"OFF"|"AUTO"`
  - `PDML_MAX_PARALLELISM=1..1000` (Partitioned DML only)
  - *GoogleSQL-only*: `ALLOW_DISTRIBUTED_MERGE=TRUE|FALSE`, `USE_UNENFORCED_FOREIGN_KEY=TRUE|FALSE`, `RANDOMIZE_QUERY_ROOT=TRUE` (mitigates high-fanout root coordinator hotspotting).
- **Table Hints**: `FORCE_INDEX=IdxName|_BASE_TABLE` (directive: errors if index missing or unusable), `GROUPBY_SCAN_OPTIMIZATION=TRUE|FALSE`, `SCAN_METHOD=...`; *GoogleSQL-only*: `INDEX_STRATEGY=FORCE_INDEX_UNION`, `SEEKABLE_KEY_SIZE=0..16`.
- **Join Hints**: `FORCE_JOIN_ORDER=TRUE|FALSE`, `JOIN_METHOD=HASH_JOIN|APPLY_JOIN|MERGE_JOIN|PUSH_BROADCAST_HASH_JOIN`, `HASH_JOIN_BUILD_SIDE=BUILD_LEFT|BUILD_RIGHT`, `BATCH_MODE=TRUE|FALSE`; *GoogleSQL-only*: `FACTORIZED_MODE=FACTORIZE_LEFT|RIGHT|BOTH`, `HASH_JOIN_EXECUTION=MULTI_PASS|ONE_PASS`.
- **Group Hint (GoogleSQL)**: `GROUP @{GROUP_METHOD=HASH_GROUP|STREAM_GROUP} BY`.
- **Function Hint (PostgreSQL)**: `DISABLE_INLINE=TRUE`.

## 5. DML, Partitioned DML (PDML), Batch Write, Transactions & Reads

### Standard DML Rules & Upsert Gotchas

- **Upsert Syntax**: Supports `INSERT OR IGNORE`, `INSERT OR UPDATE`, and `INSERT ... ON CONFLICT [(cols)] DO NOTHING | DO UPDATE SET ... [WHERE ...]`.
  - **Gotchas**: Cannot combine `INSERT OR ...` and `ON CONFLICT` in one statement; null-filtered unique indexes are **not** valid `ON CONFLICT` targets; `EXCLUDED.*` is **disallowed** inside `THEN RETURN`.
- **`UPDATE` & `DELETE`**: Always require a `WHERE` clause (use `WHERE true` for full table); no `UPDATE` with `JOIN`s; cannot update primary key columns. Nested proto/array updates must execute in strict order: `DELETE` → `UPDATE` → `INSERT`.
- **Read-Your-Writes vs Mutations**: Standard DML changes inside a read-write transaction are **immediately visible** to subsequent reads in that transaction. **Mutation API** calls (`Insert`, `Update`, `Delete`) buffer client-side and become visible only after `Commit`.

### Partitioned DML (PDML) — 6 Strict Constraints

Used for bulk backfills and bulk deletes (`UPDATE` and `DELETE` only — **no `INSERT`**, cannot run in Spanner Studio, no `PLAN`/`PROFILE`):

1. **Fully Partitionable**: Single table only; no cross-table or cross-row subqueries (otherwise fails with `BadUsage`).
2. **Idempotent**: Executed at-least-once per split partition — expressions must be safe to replay.
3. **Per-Partition Atomicity Only**: No table-wide rollback; returned row count is a **lower bound**.
4. **Concurrency & Throttling**: Hard cap is 20,000 concurrent PDMLs/DB, but keep **<= 100 concurrent** to avoid internal system-table lock contention. Throttle with `@{PDML_MAX_PARALLELISM=1..1000}`.
5. **Full-Database Split Fanout Gotcha**: PDML fans out across **all splits in the entire database** — avoid running PDML on a tiny table inside a multi-TiB database.
6. **Interleaved Parent Delete Gotcha**: Deleting parent rows that have indexed interleaved child tables can breach the 80,000 mutations/partition limit — delete child rows with PDML first, then parent rows.

### Batch Write

Available via **REST, RPC, and Client Libraries only** (not Console or `gcloud`). Submits multiple mutation groups where each group commits atomically (still capped at 100 MiB / 80,000 mutations), but groups commit **non-atomically relative to each other** in unspecified order. **No replay protection** — every mutation group MUST be idempotent.

### Transactions & Isolation Levels

| Isolation Level | Default Concurrency | Alternative Concurrency | Guarantees & Trade-Offs |
| :--- | :--- | :--- | :--- |
| **Serializable** (Default) | **Pessimistic** (shared read locks → upgraded to exclusive at commit; wound-wait deadlock prevention favoring older txn; cell granularity; blind writes use `WriterShared`) | **Optimistic** (no read locks; validates reads at commit; good for low RW contention) | Strictest external consistency via TrueTime; zero anomalies (no dirty, non-repeatable, phantom reads, or write skew). |
| **Repeatable Read** | **Optimistic** (snapshot isolation; reads take **zero locks** → far fewer RW aborts; write-write conflicts abort) | **Pessimistic** (acquires exclusive locks on `SELECT ... FOR UPDATE`, `LOCK_SCANNED_RANGES=exclusive`, and DML writes) | Ideal for read-heavy RW txns and MySQL/PG migrations. **GOTCHA**: Vulnerable to **write skew** unless guarded with `SELECT ... FOR UPDATE`! |

- **10-Second Idle Transaction Timeout**: Read-write transactions idle for **> 10 seconds** may be aborted (`ABORTED`). Keep transactions short and **NEVER call external HTTP/RPC APIs** inside a transaction block.
- **Multiplexed Sessions Priority Retry**: On retry after `ABORTED`, passing `multiplexed_session_previous_transaction_id` preserves original wound-wait lock priority (handled automatically by official client libraries).

### Reads & Timestamp Bounds

- **Strong (Default)**: Reflects all commits up to start time; contacts leader in non-leader regions unless Read Leases are enabled.
- **Exact Staleness** (`read_timestamp` / `exact_staleness`): Consistent snapshot served locally by any caught-up replica without contacting the leader.
- **Bounded Staleness** (`max_staleness` / `min_read_timestamp`): **Single-use read-only transactions ONLY**; negotiates freshest local timestamp within bound.
- **Non-Leader Staleness Rule**: Use **>= 15 seconds** staleness in dual/multi-region or custom RO topologies to reliably avoid leader round-trips. Reading older than `version_retention_period` fails with `FAILED_PRECONDITION`.
- **Parallel Bulk Reads (`PartitionQuery`)**: Query plan MUST be **root-partitionable** (single Distributed Union at root, no Distributed Cross Apply, or purely local).

## 6. Non-Relational / Key-Value Workloads

Spanner natively handles high-throughput Key-Value and semi-structured workloads without a separate NoSQL store:

- **Connectionless gRPC/HTTP2**: Multiplexed sessions eliminate traditional connection-pool exhaustion and session-pool sizing.
- **Native KV Read & Mutation APIs**: `Read`, `StreamingRead`, `Insert`, `Update`, `InsertOrUpdate`, `Replace`, `Delete` bypass SQL parsing overhead while coexisting with full SQL access over the exact same tables.
- **Semi-Structured Types**: Native `JSON` (GoogleSQL) / `JSONB` (PostgreSQL), `BYTES`, and Protobuf payloads.
- **Strong Consistency & Co-Location**: ACID multi-row/multi-table writes, unlimited strongly consistent secondary indexes, interleaved physical co-location, IAM auth, request priorities (`PRIORITY_HIGH`/`MEDIUM`/`LOW`), and Data Boost off-path analytics.

## 7. Change Streams vs Spanner Queues

### Change Streams (All Editions — CDC, Audit & Async DR)

- Captures inserts/updates/deletes as up to **10 MiB** data change record fragments; retention **`1d`–`30d`** (default **`7d`**).
- **Value Capture Types**: `OLD_AND_NEW_VALUES` (default), `NEW_VALUES`, `NEW_ROW`, `NEW_ROW_AND_OLD_VALUES`.
- **Filtering Options**: `exclude_ttl_deletes=true`, `exclude_insert`/`exclude_update`/`exclude_delete`, and `allow_txn_exclusion=true` (paired with per-transaction `exclude_txn_from_change_streams=true` to prevent infinite loops in bidirectional replication).
- **CRITICAL SENTINEL READ TIMESTAMP GOTCHA**: Read via TVF `READ_{StreamName}(...)` using `ExecuteStreamingSql` in a **strong, single-use, read-only** transaction. If `return_read_timestamp=true` is requested on a change stream query, Spanner returns a sentinel read timestamp of **`2^63 - 2`** — applications **MUST discard it**!
- **Consumers**: Direct Spanner API, Dataflow `SpannerIO`, Apache Kafka Debezium connector, and Datastream (BigQuery, BigLake Iceberg, Cloud Storage).

### Spanner Queues (Enterprise & Enterprise Plus ONLY — Transactional Pull Messaging)

Queues live inside the Spanner database so state updates and message enqueues commit in the **exact same ACID transaction** (eliminating transactional outbox relays). Delivery semantics: **at-least-once delivery** with **at-most-once acknowledgement**.

#### Queue DDL Syntax & Strict Rules

- **Allowed Columns**: **ONLY** primary key columns + mandatory `Payload`/`payload` column (`NOT NULL`; GoogleSQL `BYTES`/`STRING`/`JSON`/Proto, PG `bytea`/`text`/`varchar`/`jsonb`; cannot be part of PK). **NO other user columns allowed!**
- **Auto-Created Column**: `DeliverTime` (GoogleSQL) / `deliver_time` (PostgreSQL — avoid deprecated `DeliverTime` in PG) is created automatically as a nullable timestamp column and **MUST NOT** be declared in `CREATE QUEUE`.
- Supports `INTERLEAVE IN [PARENT]`, TTL (`ROW DELETION POLICY` / `TTL INTERVAL`), options `receive_mode='PULL'` (immutable), `disable_send`, `disable_delivery`, `locality_group`.
- **PostgreSQL `ALTER QUEUE` Gotcha**: Supports `SET OPTIONS` ONLY — cannot alter columns, PK, interleaving, or TTL.

```sql
-- GoogleSQL
CREATE QUEUE {queue_name} (
  MessageId STRING(36) NOT NULL,
  Payload JSON NOT NULL,
) PRIMARY KEY (MessageId)
OPTIONS (receive_mode = 'PULL');
```

```sql
-- PostgreSQL
CREATE QUEUE {queue_name} (
  message_id varchar(36) NOT NULL,
  payload jsonb NOT NULL,
  PRIMARY KEY (message_id)
) OPTIONS (receive_mode = 'PULL');
```

#### Send, Receive, Lease Renewal & Ack-and-Reschedule

- **Send**: Standard `INSERT INTO {queue_name} (MessageId, Payload, DeliverTime) VALUES (...)` or SDK Send mutations (`spanner.Send()`, `Mutation.newSendBuilder()`, `batch.send()`, `transaction.queueSend()`).
  - **No `UPDATE` DML on queues**: To refresh a heartbeat or reschedule, run atomic `DELETE ... ASSERT_ROWS_MODIFIED 1` + `INSERT` (or order `Ack` mutation **before** `Send` mutation in the same commit).
- **Receive**: Run via **`ExecuteStreamingSql`** inside a **strong, single-use, read-only** transaction (cannot join the receive TVF with other tables):
  - GoogleSQL: `SELECT * FROM RECEIVE_{queue_name}(max_duration => '20m', max_batch_size => 20)` (default `max_batch_size = 30`). Returns PKs, `Payload`, `DeliverTime`, `SpannerLeaseExpirationTimestamp`, `SpannerLeaseToken`, `SpannerLastBatchMessage`.
  - PostgreSQL: `SELECT * FROM spanner.receive_{queue_name}(max_batch_size => 20, priority => NULL, max_duration => '20m')` (snake_case metadata columns).
- **Leases & Token Rotation GOTCHA**:
  - Default lease = **10 seconds** (non-configurable). Renew at ~5–8s via `SELECT * FROM RENEWLEASE_{queue_name}(lease_tokens => @tokens)` (PG: `spanner.renewlease_{queue_name}(lease_tokens => ARRAY[$1])`).
  - Each renewal returns a **new** `SpannerNewLeaseToken` (`spanner_new_lease_token`) — workers **MUST carry forward the rotated token** for the next renewal! Expired/unparseable tokens return 0 rows; already-acked tokens return `NULL`.
- **Ack-and-Reschedule**: For long-running tasks or custom backoff, atomically `DELETE ... ASSERT_ROWS_MODIFIED 1` + `INSERT` with a future `DeliverTime` and checkpoint payload. Unacked messages retry automatically with backoff during hour 1, then **once per hour** thereafter.

#### At-Most-Once Processing & The `ASSERT_ROWS_MODIFIED` Trap

- **Unknown Commit Status (`DEADLINE_EXCEEDED` / `UNAVAILABLE`)**: Client libraries never auto-retry commits with unknown status (multiplexed sessions shield against client disconnects, not frontend crashes).
- **CRITICAL `OUT_OF_RANGE` GOTCHA**: Guard acknowledgement inside your business RW transaction with `DELETE FROM {queue_name} WHERE MessageId = @id ASSERT_ROWS_MODIFIED 1` (or `Ack` mutation). If a duplicate worker hits an already-acked message, `ASSERT_ROWS_MODIFIED 1` fails with **`OUT_OF_RANGE`** — **THIS FAILURE IS STATEMENT-LEVEL ONLY! Spanner does NOT automatically roll back the transaction!** You MUST propagate the error out of the transaction runner (or explicitly call `Rollback()`); **NEVER swallow `OUT_OF_RANGE` and commit**, or business writes will apply twice.

```sql
-- Inside ONE Read-Write Transaction (GoogleSQL at-most-once ack + business state update):
-- 1. Guard ack: raises OUT_OF_RANGE if already acked (MUST abort/rollback transaction!)
DELETE FROM {queue_name} WHERE MessageId = @message_id ASSERT_ROWS_MODIFIED 1;
-- 2. Apply business state change atomically in the same commit
UPDATE {table_name} SET status = 'PROCESSED' WHERE id = @entity_id;
-- Optional ack-and-reschedule (instead of final ack): INSERT next checkpoint with future DeliverTime
-- INSERT INTO {queue_name} (MessageId, Payload, DeliverTime)
-- VALUES (@next_message_id, @checkpoint_json, TIMESTAMP_ADD(CURRENT_TIMESTAMP(), INTERVAL 5 MINUTE));
```

#### Queue Limits, FGAC Gotchas, Monitoring & Patterns

- **Hard Limits**: **100 queues/instance** (`>= 1` node; scales proportionally below 1 node, e.g., 200 PUs = **20 queues**); **1,000 active receive queries** with identical arguments per queue; **2,000 concurrent receive TVFs per project per region** (`RESOURCE_EXHAUSTED` above limit); keep payloads **< 4 KB** (store larger blobs out-of-band in a table or GCS); no `AddSplits` API on queues (interleave in a parent table to inherit splits); cannot create queues in named schemas; geo-partitioned queues are not data-residency compliant after `DROP PARTITION`.
- **3 Critical Queue FGAC Gotchas**:
  1. `EXECUTE` on `RECEIVE_*` does **NOT** require `SELECT` on the queue, and `SELECT` on the queue does **NOT** grant `EXECUTE` (opposite of Change Streams!).
  2. **GoogleSQL Strict Case-Sensitivity**: `GRANT`/`REVOKE` on queue TVFs is strictly case-sensitive (`RECEIVE_OrdersQueue`, NOT `receive_OrdersQueue` → fails with `TABLE_FUNCTION not found`).
  3. **PostgreSQL `spanner.` Prefix Trap**: `GRANT EXECUTE ON FUNCTION spanner.receive_{queue_name}` uses `spanner.` as a function-name prefix, **NOT** a schema — queue functions live in `SCHEMA public`, so `GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA spanner` FAILS! Column-level privileges are unsupported on queues.
  ```sql
  -- GoogleSQL Queue FGAC Personas (exact case on RECEIVE_/RENEWLEASE_ required!)
  GRANT INSERT ON QUEUE OrdersQueue TO ROLE queue_producer_role;
  GRANT EXECUTE ON TABLE FUNCTION RECEIVE_OrdersQueue, RENEWLEASE_OrdersQueue TO ROLE queue_consumer_role;
  GRANT DELETE ON QUEUE OrdersQueue TO ROLE queue_consumer_role;
  GRANT SELECT ON QUEUE OrdersQueue TO ROLE queue_auditor_role;

  -- PostgreSQL Queue FGAC Personas (spanner. is a function-name prefix inside SCHEMA public)
  GRANT INSERT ON TABLE orders_queue TO queue_producer_role;
  GRANT EXECUTE ON FUNCTION spanner.receive_orders_queue, spanner.renewlease_orders_queue TO queue_consumer_role;
  GRANT DELETE ON TABLE orders_queue TO queue_consumer_role;
  ```
- **Monitoring & Production Patterns**: Track `spanner.googleapis.com/queue/{buffered_ready_messages,message_send_count,message_ack_count,oldest_unacked_message_age,lease_expiration_count}` (60s sampling, 120s lag; no queue `SPANNER_SYS` tables). Standard patterns: **Temporal batching** (`DeliverTime = RoundDown(now, delay) + delay` + hash jitter to avoid spikes), **Dirty flag** deduplication, **Polymorphic queues**, and **Worker heartbeat** refresh.
